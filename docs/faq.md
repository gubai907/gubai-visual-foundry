# 常见问题

**简体中文** | [English](faq.en.md)

[返回首页](../README.md) · [安装教程](installation.md)

## 安装后会自动生成图片吗？

技能会按请求编写提示词、编辑要求或分镜。实际生成需要你明确提出，并有可用的生成工具。只要求提示词时，不会把文字输出当作图片交付。

## 必须安装 Python 吗？

日常编写提示词不需要。维护者运行包结构与回归检查时才需要 Python 3.10 或以上版本，无第三方依赖。

## 必须指定平台吗？

不必。没有指定时直接使用通用自然语言表达。指定任意视觉平台时，可按它的输入格式与能力自行调整，也可遵循你提供的格式。仓库内置的常用规则不限制平台范围；参数、参考图数量和编辑能力以实际环境为准。

## 我应该提供几张参考图？

提供任务需要的图片即可，并标明各图负责的内容。图像数量上限取决于所用平台。没有必要为不涉及人物的产品任务提供人物参考。

## 只有 SKILL.md 可以使用吗？

完整安装需要保留支持目录，因为入口会读取任务模块、保留规则、适配器和检查规则。单独复制入口无法提供完整工作流。

## 为什么找不到技能？

检查安装目录是否受当前环境支持、文件夹是否直接包含 `SKILL.md`、是否出现重复嵌套；在下一轮对话检查，仍未出现时重启。详细路径见安装教程。

## 能保证同一张脸或编辑区域外完全不变吗？

不能仅凭提示词保证。技能会明确保留要求、参考职责与检查重点；结果仍受工具能力影响，需要查看实际输出。像素级保留需要合适的编辑方式和结果比对。

## 可以把自己的品牌资料放进去吗？

可在本地项目中提供所需品牌与角色资料。公开仓库和安装包应只保留通用接口及虚构示例；自己的照片、凭据、历史记录和业务资料放在外部私有位置。

## .gitignore 会阻止所有隐私文件上传吗？

不会。它只能帮助忽略匹配的未跟踪文件，不能清理已提交的内容，也不能代替网页上传前的检查。公开前需检查文件、内容和提交历史。

## Source code ZIP 和安装包有什么区别？

源码 ZIP 是 GitHub 自动生成的仓库快照，文件夹名可能带版本或分支后缀。项目提供的 Release 安装包统一使用 `gubai-visual-foundry` 顶层文件夹，并附对应说明和校验值；仅在 Release 实际发布后可下载。

## 可以输出中英文两版吗？

可以，在请求中说明“输出完整中英文两版”，两版应保留相同的主体、参考职责、修改范围和限制。只需要一种语言时明确指定即可。首页和教程提供对应的中英文文件，不要求实际输出必须跟随文档语言。
